# Example 1: Adam cPINN experiments

This directory publishes the Adam-optimized conservative physics-informed neural network (cPINN) experiments for Example 1. Each case models the same two-subdomain problem with a different moving interface:

| Case | Directory | Interface |
| --- | --- | --- |
| Linear | `Example1_adam/linear` | Linear in time |
| Oscillatory | `Example1_adam/oscillatory` | Linear trend with a sinusoidal perturbation |
| Quadratic | `Example1_adam/quadratic` | Quadratic in time |


## Requirements

The notebooks were inspected with Python 3.11.5. Their pinned direct runtime dependencies are listed in [`requirements.txt`](requirements.txt).

Install the packages from the repository root:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m ipykernel install --user --name rd2 --display-name "Python (RD2)"
```

For GPU execution, install the `torch==2.12.1` wheel that matches the system CUDA driver. The notebooks automatically select CUDA when it is available and otherwise run on CPU. CPU execution is supported but training is resource-intensive.

## Saved artifacts and data

No external dataset is required. The reference solution is generated by `exact_solution.ipynb` and saved as NumPy arrays. Published Example 1 artifacts are located outside this directory at:

```text
.../example1_<case>/run_<n>/
```

For evaluation, the selected run must contain:

```text
U_exact.npy                 # Reference solution used for training and error calculation
ffm/best-cp.ckpt            # Best left-subdomain model state dictionary
ffp/best-cp.ckpt            # Best right-subdomain model state dictionary
loss_adam.csv               # Training-loss history used by test.ipynb
```

The provided `run_<n>` directories for `linear`, `oscillatory`, and `quadratic` include these files, along with `U_pred.npy`, figures, metrics, and periodic checkpoints. Checkpoints are PyTorch state dictionaries; load them only when they come from a trusted source.

## Run an existing published result

This is the quickest way to reproduce the figures and metrics from an included run.

1. Activate the environment above and start Jupyter from the repository root:

   ```bash
   jupyter lab
   ```

2. Open one of the case-specific `test.ipynb` notebooks.

3. In the checkpoint configuration cell, set `checkpoint_dir` and `checkpoint_path` to the local run directory. For example, for the linear case:

   ```python
   from pathlib import Path

   repository_root = Path.cwd()
   checkpoint_dir = repository_root / "SR/weights_adam/example1_linear"
   checkpoint_path = checkpoint_dir / "run_3"
   checkpoint_path_ffm = checkpoint_path / "ffm/best-cp.ckpt"
   checkpoint_path_ffp = checkpoint_path / "ffp/best-cp.ckpt"
   ```

   Use `example1_oscillatory` or `example1_quadratic` for the other cases. 

4. Run all cells in order: **Run → Run All Cells**. The notebook loads both subnetworks, compares the prediction with `U_exact.npy`, and writes plots, timing information, `info2.txt`, and `U_pred.npy` to `checkpoint_path`.

## Generate a new run

Use this sequence for each case. Do not mix artifacts across cases: the reference solution, interface definition, model checkpoints, and test notebook must all use the same case.

1. Choose `linear`, `oscillatory`, or `quadratic`, and open that case's `exact_solution.ipynb`.

2. Run all cells to compute `U_exact` (and the related transformed solution arrays). The notebooks use a 5,000-by-5,000 space-time grid, so allow substantial memory and runtime.

3. Create a new output directory and save the generated reference solution. For example, for a new linear run:

   ```bash
   mkdir -p SR/weights_adam/example1_linear/run_4/ffm
   mkdir -p SR/weights_adam/example1_linear/run_4/ffp
   ```

   In a new cell at the end of `exact_solution.ipynb`, run:

   ```python
   from pathlib import Path
   import numpy as np

   run_dir = Path.cwd() / "SR/weights_adam/example1_linear/run_4"
   np.save(run_dir / "U_exact.npy", U_exact)
   ```

   Replace `linear` with the selected case. The published exact-solution notebooks calculate `U_exact` but do not save it automatically.

4. Open the matching `train.ipynb`. Update its `checkpoint_dir` to the new `run_4` directory and ensure that its `ffm` and `ffp` subdirectories exist. The training notebook reads `U_exact.npy` from this directory and does not create the output directories itself.

5. Run all training cells in order. The configured run uses 100,000 Adam iterations and produces `best-cp.ckpt` for each subnetwork, periodic checkpoints, `loss_adam.csv`, `info1.txt`, training-point plots, and timing information.

6. Open the matching `test.ipynb`, point `checkpoint_path` to the same new run directory, then run all cells in order. It expects `U_exact.npy`, both best checkpoints, and `loss_adam.csv` created in the preceding steps.

## Reproducibility notes

- Run notebooks from the repository root so paths such as `SR/weights_adam/...` resolve correctly.
- Execute cells in notebook order. The notebooks define arrays, model architecture, and interface functions in earlier cells that are required later.
- The saved artifacts are overwritten when the same `run_<n>` directory is reused. Use a new run number for new experiments.
- The exact-solution grid size, model architecture, optimizer settings, interface function, and time range are set directly in each notebook. Keep those settings aligned across the exact-solution, training, and test notebooks for a valid comparison.
